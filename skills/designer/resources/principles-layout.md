# L1 原理：版式布局基础
> 学科共识，非项目特定。Gestalt 完形 / 信息层级 / 视觉流 / 网格系统 / 留白，是通用排版学科原理，不依附任何单一品牌。设计时以此为基础约束，再叠加品牌层。

---

## 一、Gestalt 完形心理学 8 定律

**本质**：人的视觉会自动把分散元素「脑补」成整体。设计者要利用这种自动补全，减少用户去「读」的成本。判断标准：用户 0.1 秒内能不能一眼看出「这块是一组」。

### 1. 临近律 (Proximity)
- **规则**：距离近的元素被视作一组。**间距是分组的第一语言，优先级高于边框和颜色。**
- **UI 示例**：表单的「标签 + 输入框」间距 < 输入框之间的间距；卡片标题与正文间距 < 卡片与下一卡片间距。
- **执行值**：组内间距 8px，组间间距 16px；卡片间距 ≥ 24px。要让用户能看出「1 个组」而不是「所有东西连成一片」。

### 2. 相似律 (Similarity)
- **规则**：形状/颜色/大小/纹理相似的元素被归为一类。**同类信息用同一视觉语言，别让不同类用同一种语言。**
- **UI 示例**：所有主按钮用同一主色；所有次级按钮统一描边样式；所有链接统一同一色 + 下划线。
- **执行值**：同层级的交互控件只用 1 种颜色 + 1 种形状。切换颜色即切换语义，绝不同色复用。

### 3. 闭合律 (Closure)
- **规则**：不完整的图形，大脑会自动填成完整形状。**适合用留白/残缺制造高级感，但别在关键内容上玩命省钱。**
- **UI 示例**：加载中的骨架屏、头像的圆形裁剪、图标断线化设计（笔画断开仍可识别）。
- **执行值**：只允许在「装饰性图形」用闭合；文字、按钮、功能图标必须完整可辨，不能靠用户脑补。

### 4. 连续律 (Continuity)
- **规则**：视觉上沿平滑路径延伸的元素被视作连续体，**引导视线方向。**
- **UI 示例**：时间轴的竖线把节点串成一路；面包屑导航的箭头链；步骤条。
- **执行值**：长流程（注册、结算、引导）必须用连续视觉主线（进度条/时间轴）串起来，让用户知道「我在哪儿、接下来去哪」。

### 5. 对称律 (Symmetry)
- **规则**：对称元素被视为一个整体，给人稳定、平衡、可信。**对称 = 权威/官方，不对称 = 动感/现代。**
- **UI 示例**：登录页居中对称布局；产品定价表的对称三列；hero 区居中标题。
- **执行值**：**权威型**页面（登录、结算、官网首屏）多用居中对称；**产品型/数据型**界面用非对称，但整体重心要稳，别出现一头沉。

### 6. 共同命运律 (Common Fate)
- **规则**：朝同一方向运动/变化的元素被视作一组。**是动效分组的核心依据。**
- **UI 示例**：列表项批量编辑时一起上浮 + 变色；同组卡片 hover 时同步位移；删除动画整组一起淡出。
- **执行值**：同组元素必须「同动画、同节奏、同时长」（同时 start、同步结束，时长差 <100ms），否则用户会认为它们在拆伙。

### 7. 图形-背景律 (Figure-Ground)
- **规则**：视觉自动区分「图形」（前景，要看的）和「背景」（衬底）。**焦点 vs 环境。**
- **UI 示例**：浮层弹窗（高对比前景 + 半透明暗色遮罩）；卡片内容与页面底色；模态窗。
- **执行值**：需要强调的元素提高对比度（背景与前景亮度差 ≥ 30%）；需要退后的元素弱化（用浅灰、降低饱和度）。前后景对比不足，用户就「找不到重点」。

### 8. 简洁律 (Prägnanz / Good Figure)
- **规则**：人倾向于把复杂图形视为最简单的形态。**越规则、越对称、越统一的形态越易被接受。**
- **UI 示例**：圆角卡片比锯齿卡片更舒适；圆（头像/图标）比多边形更高级；用「统一的圆角/间距/色板」降低认知负担。
- **执行值**：一套界面切圆角≤3 档（如 4/8/12px），颜色≤5 档，字体<4 档。**规范化的重复本身就是在用简洁律。**

## 二、信息层级：视觉权重排序

**本质**：每一步决定用户眼睛先看什么。一句话——**重要信息权重高，次要信息权重低，别让次要信息抢了主要的戏。**

### 权重优先级（从高到低）
1. **位置**：左上 > 右上 > 左下 > 右下（用户习惯起点）。**位置是第一权重，比字号更能决定注意力。**
2. **字号**：标题 > 正文 > 辅助说明。
3. **颜色 / 对比度**：高饱和度/深色 > 低饱和/浅色；强调色 > 中性灰。
4. **字重**：粗体（600/700）> 常规（400）> 细（300）。**同字号下改字重是低成本提速权重的方法。**
5. **留白**：周围留白越多，越被注意（孤立感 = 重要感）。
6. **位置关系 / 层级位置**：越靠近顶部/越靠左，越先被读。

### 可执行的层级梯度设计

**H 尺寸阶梯（正文基准 16px / 1rem）**
| 层级 | 字号 | 字重 | 颜色 |
|------|------|------|------|
| H1 | 32–40px | 700 | 近黑 #111827 |
| H2 | 24–28px | 700 | 近黑 |
| H3 | 18–20px | 600 | 深灰 #374151 |
| 正文 | 15–16px | 400 | 深灰 #4B5563 |
| 辅助说明 | 13px | 400 | 中灰 #6B7280 |
| 占位/页脚 | 11–12px | 400 | 浅灰 #9CA3AF |

**规则**
- 一个页面标题字号档位 ≤ 4 档，**别用 5 种以上字体大小**。
- 强调一个词：优先**加字重**或**改强调色**，别只放大字号（会破坏基线）。
- 正文到辅助说明的对比要能拉开（灰阶差一级），否则用户分不清主次。
- **标题、正文的行高**：标题行高 1.2，正文行高 1.5–1.6，说明文字 1.4。行高不足会挤成一坨。
- 同屏同时出现「主 CTA + 副 CTA」，主 CTA 用实心高对比，副 CTA 用描边/幽灵样式，**对比要一眼可分**。

## 三、视觉流：引导视线运动路径

**本质**：页面不是平铺信息，而是一条「导览路线」。设计者决定用户先看哪、后看哪。

### 两种基础模式
1. **F 型（内容密度高/文字多——数据后台、News、文档）**
   - 扫视路径：**左上标题 → 左列扫一遍 → 水平方向扫标题/关键词 → 快速下移。** 类似字母「F」。
   - 适用：**信息密集**的页面，用户要快速扫。
   - 要求：把**关键词/结果/关键数字放每行开头**（左对齐短词），别让用户在一长段里找重点；把高频操作的按钮/入口放在左上方热区。

2. **Z 型（高视觉冲击/营销——官网首屏、Landing、Hero）**
   - 扫视路径：**右上到左上（第一扫）→ 对角线下来 → 左下（停留）**，形如字母「Z」。
   - 适用：**视觉传达**优先的页面，信息少、画面强。
   - 要求：**左上放品牌/标题，右下角（Z 的落点）放主 CTA**；中间用视觉元素（图、色块、大数字）引导对角线走向。

### 层级引导（引导用户走主路径的 6 个钩子）
1. **首屏必须交代「这页是干嘛的」**：标题 + 副标题 + 一个主 CTA，三者成一线路（视线的起、承、舍）。
2. **每一个视觉锚点（抓眼球的大标题/大图）都要指向下一个内容**——看完 A 自然往下看 B，否则用户会迷路或跳出。
3. **把最重要的 CTA 放在扫视模式的落点**：F 型的右上/右侧、Z 型的右下方。
4. **用箭头/进度/编号做显式引导**（步进式流程、教程、结算步骤）。
5. **从上到下/从左到右**是默认流，**别让元素「倒着长」**（如标题在右下、正文在左上）会造成阅读跳跃。
6. **滚动页面要「有节奏」**：每屏一个视觉高潮（大标题/大图），屏与屏之间留呼吸，别每屏都同样密度。

**执行判断**
- 高信息密度的产品/后台页面 → **F 型**（关键词前置、左列快速扫）。
- 高视觉冲击的营销/首屏 → **Z 型**（品牌左上 + CTA 右下）。
- 拿不准时：**先用 F 型兜底**（内容优先），再按品牌调性升级为 Z 型。

## 四、网格系统

**本质**：解决「元素往哪放、间距是多少」。网格让无序的碎片变成有序的系统，是「对齐」的工程化实现。

### 1. 列数
- **12 列**：最常用。**12 能被 2/3/4/6 整除**，组合最灵活——三分栏（4+4+4）、双栏（6+6）、侧边栏（3+9）……都会得到整数，不会出现小数对齐误差。
- **24 列**：**更精细**，适合字段非常多、需要精确列宽的复杂数据后台/仪表盘。
- **选择**：营销官网/常规页面用 12 列；数据后台/复杂表单用 24 列。

### 2. 间距（Gutter / Gap）
- **列间距**：桌面 24px（栅格 gutter），移动端 16px。
- **内容左右安全边距（Margin）**：桌面 ≥ 24px，平板 16px，手机 16px。
- **执行规则**：横向排列的模块 gap 用 16 或 24；垂直排列的模块间距用 24 或 32；卡片内部 padding 8–16。**全站只允许一组「标准间距」，不许每块自定义。**

### 3. 模块化缩放比例：8pt 系统
**这是排版真理。** 所有尺寸（间距、圆角、尺寸、图标、字号、阴影）都必须落在 **8 的倍数**（或用 4 的倍数做细粒度补充）上。

- **8pt 阶梯**：4 / 8 / 12 / 16 / 24 / 32 / 40 / 48 / 64 / 80 / 96……（以 4 递进）。
- **通用间距表**：4（微间距）、8（组内元素间）、16（组间）、24（区块间）、32（大区块）、48%（页面级分隔）。
- **为什么**：人的眼对「一致的比例」更舒适；8 是界面显示的最小公倍数，被主流系统（Material/Apple）采用，**保证换色换皮肤时组件不错位**。
- **例外**：正文行字高、细粒度图标线宽可以用 4 的倍数微调，但绝不允许出现 6/10/14/18/20/22 这类「非 4 倍数」的间距。
- **圆角阶梯**：4 / 8 / 12（或 8 / 12 / 16），一套只取 2–3 档。

### 4. 落地执行清单
- 建立 CSS 变量：`--space-1: 4px; --space-2: 8px; --space-3: 16px; --space-4: 24px; --space-5: 32px; ...`
- 组件内部用 `--space-2`，组件之间用 `--space-4`，页面节之间用 `--space-5`。**从变量取，不硬编码。**
- **对齐铁律**：同一列里所有元素**左对齐**；同一行的基线**水平对齐**；卡片、按钮、图片的**左右边缘必须落栅格线**，不许错位 1px。
- 断点：移动 <576px（4 列）、平板 576–1024px（8 列）、桌面 ≥1024px（12 列）。

## 五、留白与呼吸（Negative Space）

**本质**：留白不是「空的」，是「主动的设计」。它负责**分组**（区分模块）、**对强调**（孤立感 = 重要感）、**引导流**（视线移动的停顿）。**留白是排版的第一生产力，比加边框/加背景色更能解决「挤」。**

### 1. 留白的三种用途
1. **分组（Segmentation）**：用「块间距」替代「分隔线」。**相邻元素间距（组内）< 不同元素间距（组间）**，让用户自动分组。**能用间距就不用分隔线。**
2. **强调（Emphasis）**：重要元素周围留白越多，越显眼。**想让一个元素重要，就给它多一点呼吸空间，而不是加粗变红。**
3. **对流（Flow）**：留白是视线移动的「停顿点」，让扫视有节奏、不疲劳。

### 2. 对齐
- **留白本身必须对齐栅格**。所有空白边界落在网格线上，空白才有「秩序感」；否则看起来是「没排好」。
- 同组元素间距一致（如 8px），跨组用更大间距（如 24/32px）——**间距的唯一性制造分组**。
- **水平留白对齐**：卡片、图像、文本的左边缘必须在同一条栅格竖线上，**视觉上拉出一条「隐形垂直线」**。

### 3. 间距阶梯（全站唯一标准）
| 用途 | 推荐值 |
|------|--------|
| 元素内部的微间距（图-文相邻、图标-标签） | 4–8px |
| 组内元素间距（表单字段之间、列表项之间） | 8px |
| 组间间距（卡片标题-正文、块与块） | 16–24px |
| 区块间距（模块与模块） | 24–32px |
| 页面级分隔（section 与 section，换视觉高潮） | 48–96px |

### 4. 留白常见错误（必避）
- **塞满**：信息密度过大，用户「没地方落脚」。**宁可删信息，别删留白。**
- **没有主次**：所有元素间距一样，用户分不清组，页面「一坨」。
- **留白没有落在栅格上**：看似空白实则错乱。
- **用边框/背景色代替留白**：能靠间距分组就先用间距，边框是最后手段（边框视觉重量大，用多了会「框死」页面）。

## 附：五节速查表（设计前过一遍）

| 维度 | 一句话规则 | 核心数值 |
|------|-----------|---------|
| Gestalt | 用距离/相似/对比让用户 0.1s 自动分组 | 组内 8px / 组间 24px |
| 信息层级 | 位置 > 字号 > 颜色 > 字重 > 留白 | 标题档 ≤ 4 档 |
| 视觉流 | 内容密用 F 型，营销强用 Z 型 | F：关键词前置；Z：CTA 右下 |
| 网格 | 12 列（后台 24 列）全站唯一间距 | 列间距 16–24px |
| 留白 | 主动留白、栅格对齐、间距唯一 | 阶梯 4/8/16/24/32/48/96 |

> **总纲**：先定网格（列数 + 8pt 间距），再排信息层级（谁最重要），再用留白分组，最后用视觉流（F/Z）串成一条导览路线，全程遵守 Gestalt（让用户自动脑补分组）。这五件事做完，版式就立住了；再做色彩、字体、品牌，是锦上添花。
