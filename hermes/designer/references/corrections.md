# L3 反馈闭环 · 纠正记录

> 用户每次设计被纠正/表扬，就在这里追加。agent 设计前必读此处，避免重复踩坑。
> 这是让设计知识库「越用越聪明」的关键——不是静态手册，是活的反馈系统。

---

## 使用规则

- **每次用户纠正设计** → 在本文件追加一条（日期 + 纠正内容 + 根因 + 正确做法）
- **每次用户表扬设计** → 也追加（记住什么做对了）
- **典型踩坑** → 单独 `pitfalls/` 记录，顶部有速查表

---

## 📌 速查表（设计前必扫）

| 坑 | 正确做法 |
|:--|:--|
| 手搓 `<table>` | 用 OpsDataTable |
| 硬编码 `#06b6d4` | 用 `T.color.accent` |
| Header 当子元素 | 用 `header=` prop |
| 图表 `Math.sin()` 假数据 | 引真实 API |
| 过度装饰（渐变/glow/emoji） | 克制，只变边框 |
| 中文"编/删"按钮 | Lucide 图标 |
| 10/11px 字号 | ≥12px |

## 一、纠正记录（按时间倒序）

### 2026-08-22 · 用户洞察"缺素材库"
- **纠正**：知识库只有知识，缺现成素材库——"巧妇难为无米之炊"
- **根因**：设计能力不能全靠手搓，图标/图表/动效/组件都有现成库
- **正确做法**：建 L0 素材库 `assets-index.md`，优先用现成库

### 2026-08-19 · 头部间距要统一
- **纠正**：keywords/knowledge 页头和其他页间距不一致
- **根因**：Header 当子元素传进 OpsPageShell，被 py-6 推了 24px
- **正确做法**：Header 必须用 `header=` prop 传入

### 2026-08-06 · 卡片边框对比度
- **纠正**：卡片边框 `rgba(255,255,255,.05)` 太淡看不清
- **正确做法**：提升到 `.08`，卡片 vs 面板 ≥8pt RGB 差

### 2026-07-27 · 设计灾难（"丑死了"）
- **纠正**：盲加渐变背景/::before色条/大图标块，用户暴怒
- **根因**：没先截图看效果，违反"克制装饰"
- **正确做法**：参考优先（先问 Linear/Stripe）+ screenshot 验证 + 做1个原型确认再铺开

### 2026-07-27 · 用户选 Linear 作参考
- **纠正**：之前用 Datadog 风格（渐变/彩色条/阴影），被 revert
- **正确做法**：运营后台 = Linear 极简，见 `reference-linear.md`

## 二、表扬记录（什么做对了）

### 2026-08-22 · 智能性设计（L2 项目规范智能管理）
- 用户提出两个关键智能性问题：①新项目无 token 是否要问风格 ②已有基础是否自动提取
- **做对了**：不会机械复制模板，而是判断环境——冷启动走"询问风格"，已有基础走"自动提取"，每个 token 标注来源
- **实证**：用快手项目跑了路径B（它已有 392 token 类 vs 2 裸色），自动生成了 `L2-projects/kuaishou.md`
- **核心洞察**：skill 的智能性 = 能判断"该问用户还是能自己提取"，不靠死板规则

### 2026-08-22 · 参考解剖质量
- 4 个参考文件（Linear/Stripe/Vercel/Claude）+ 分桶索引被认可
- **做对了**：蒸馏成可执行规则而非文档抄录

### 2026-08-22 · 端到端验证真的跑通了
- 用户质疑"光存在不行，得验证从头到尾可用性"
- **做对了**：用子代理（无 XGEO 污染）实测快手 OverviewPage——加载知识库→选 Linear 参考→遵守 GATE 1 现有组件/语义 token→GATE 2 截图→GATE 3 构建，全部走通
- **洞察**：验证 skill 不能用"我知道怎么设计"的当前 session 测，必须用隔离的子代理，才能测出"教另一个 agent"是否可行

### 2026-08-22 · 增强B 实测发现边界（智慧来自真跑）
- **做对了**：用快手项目实测增强B（token 冲突检测），抓到一个"假阳性"
- **发现**：`<table>` 命中但真正违规要看**业务页面**——`components/ui/DataTable.tsx` 封装组件内部用原生 `<table>` 是**合法实现**，不是手搓
- **改进**：检测规则加"排除 components/ui/ 封装目录"，避免把组件内部合法实现误报成业务违规
- **洞察**：smart skill 的规则要靠真实项目测试去校准，不能只靠理论。这次实测让增强B 更准了

## ⚠️ 隐私红线（重要教训）

### 2026-08-22 · 备案号泄漏公开仓库
- **错误**：把企业备案号（〔企业备案号〕）+ 公司名（〔企业名〕）放进了 GitHub 公开仓库
- **根因**：拷贝 XGEO 项目规范时没筛敏感信息
- **正确做法**：公开仓库禁含 备案号/公司名/密码/内部域名；用 `git filter-repo` 从历史彻底清除 + 强制推送
- **经验**：用户明确"备案号是私密信息"——任何企业标识信息默认不进公开仓库
