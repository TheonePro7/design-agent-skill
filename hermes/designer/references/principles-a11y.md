# 无障碍 (A11y) · L1 原理

> **学科共识，非项目特定。** 本文是通用无障碍学科原理，不绑定任何具体品牌、产品或代码库。目标：给出**可执行规则**，不是教科书抄录。每节是可以直接对照检查的清单。

---

## 0. 一句话原则

> **任何用户都能用键盘、屏幕阅读器、和不依赖颜色的方式，完成每一个功能。**

三条底线：
1. 所有交互元素都能**只靠键盘**到达并用 Enter / Space 触发。
2. 屏幕阅读器读到的信息，**不少于**视觉上看到的信息。
3. 任何状态都不能**只靠颜色**来表达。

---

## 1. WCAG 2.2 四原则（核心）

WCAG 的四大原则各有明确验收动作。逐条对上号：

### 1.1 可感知（Perceivable）
- 内容对感官可获取：文字、图像、音频、视频都要有替代形式的呈现。
- **规则：** 所有**非文本内容**（图标、图片、图表、装饰性信息）都必须有文本替代。

### 1.2 可操作（Operable）
- 界面组件和导航必须可操作。
- **规则：** 键盘能完成全部操作；用户有足够时间完成任务（不使用过短的自动消失提示）；不诱发癫痫（避免大面积高频闪烁 ≥3 次/秒）。

### 1.3 可理解（Understandable）
- 信息与操作必须易读易懂、行为可预测。
- **规则：** 页面有明确语言声明（`lang` 属性）；输入错误有具体提示且不阻止纠正；交互组件在激活前后**保持稳定**（不突然跳位）。

### 1.4 稳健（Robust）
- 内容能被各种辅助技术（屏幕阅读器、盲文机、语音输入）可靠解析。
- **规则：** 使用**原生语义 HTML**，保证解析器能理解结构；自始至终使用配对标签、正确嵌套。

> 本文件后续每节会回到这四原则，标注它主要服务哪一条。

## 2. 键盘导航

**服务原则：可操作 (Operable)。** 这是最常见的可访问性硬伤来源。

### 2.1 Tab 键顺序（Tab 顺序必须符合视觉顺序）
- [ ] Tab 焦点从左到右、从上到下移动，与视觉布局逻辑一致。
- [ ] 所有可交互元素都在 Tab 序中可达；不可交互元素（纯文本、图片）**不得**进入 Tab 序。
- [ ] **规则：** 不要用 `tabindex` 把不应交互的元素变成焦点，也不要让可交互元素丢失焦点。

### 2.2 焦点圈必须有（Focus Visible）
- [ ] **强制规则：** 任何元素获得键盘焦点时，必须出现清晰的焦点轮廓（`outline` / `:focus-visible` / focus ring）。
- [ ] 焦点圈颜色与背景对比度 ≥ 3:1，且不止靠颜色区分（用明显的描边宽度或形状）。
- [ ] 清除默认 `outline: none` 时，必须自己实现替代焦点样式。
- [ ] 用鼠标点击时焦点圈可以弱化（`focus-visible` 键盘专属），但**键盘导航时必须有**。

### 2.3 Esc 关闭弹窗（模态/弹层）
- [ ] **强制规则：** 所有弹窗、下拉菜单、抽屉、模态框按 `Esc` 必须能关闭。
- [ ] 打开弹窗后，焦点**立即移入**弹窗内（首个可聚焦元素）。
- [ ] 弹窗打开期间，Tab **被锁定在弹窗内部**（焦点陷阱），不能落到背景页面。
- [ ] 弹窗关闭后，焦点**返回**触发按钮（回到之前的位置）。
- [ ] 弹窗层级用原生 `<dialog>` 或在 DOM 上做正确管理，不要靠 `z-index` 硬撑。

### 2.4 Skip link（跳转到主内容）
- [ ] 每个页面顶部放一个"**跳到主内容 / Skip to main content**"链接。
- [ ] 默认它不可见，**仅在**键盘按 Tab 后首次聚焦时显示（`focus` 时出现）。
- [ ] 锚点目标指向实际的 `<main id="main">` 或 `h1` 附近。
- [ ] 收益：键盘用户无需每页重复 Tab 过导航几十次。

## 3. 对比度与可见性

**服务原则：可感知 (Perceivable)。**

### 3.1 文本对比度（WCAG AA）
- [ ] **正文文本 ≥ 4.5:1**（对背景）。
- [ ] **大文本 ≥ 3:1**（≥24px 或 ≥19px 加粗）。
- [ ] **图形元素、图标、UI 组件边界 ≥ 3:1**（如按钮描边、图标轮廓、输入框边框）。
- [ ] **规则：** 灰色小字 + 浅背景是重灾区，一律测量后放行。
- [ ] 计算工具：用 WCAG 对比度计算器或公式 `(L1+0.05)/(L2+0.05)` 验证，不靠肉眼。

### 3.2 焦点可见（详见 2.2，此处强调数值）
- [ ] 焦点圈对比 ≥ 3:1，且面积足够大（描边 ≥ 2px 或外发光垫底）。

### 3.3 文本缩放 200% 不破版
- [ ] **强制规则：** 浏览器文本放大到 200% 时，布局**不丢失信息、不横向溢出、不遮挡重叠**。
- [ ] 内容可以滚动，但**不能被裁切、不能互相覆盖**。
- [ ] 用相对单位（`rem`/`em`）而非固定 `px` 设置字体；避免定死高度导致缩放后截断。
- [ ] 验证：浏览器缩放到 200% 或系统放大 200%，逐页截图检查。

## 4. 语义化 HTML 与 ARIA

**服务原则：稳健 (Robust)。** 这是最容易滥用、也最常见的错误源头。

### 4.1 优先用原生元素，而非 div + 自定义
- [ ] **规则：先用原生，再谈 ARIA。** 能用 `<button>` 就别用 `<div onclick>`，能用 `<a href>` 就别用 `<div>` 模拟链接。
- [ ] 原生 `<button>` / `<a>` / `<input>` / `<select>` 自带键盘交互、焦点管理、屏幕阅读器角色，**零成本**。
- [ ] `<div>` / `<span>` 加 `onclick` 是**反模式**：默认不可聚焦、不可键盘触发、无角色、无语义。

### 4.2 ARIA role / label 正确用法
- [ ] **ARIA 不改变可访问性，除非正确使用；错误使用比不用更糟。**
- [ ] 只在原生元素缺失语义时才加 `role`（如 `role="tablist"`、`role="dialog"`、`role="slider"`）。
- [ ] 每个有角色但无可见文本的元素，必须有 `aria-label` 或 `aria-labelledby`。
- [ ] **禁止：** 给原生元素加与其语义冲突的角色（如给 `<button>` 加 `role="link"`）。
- [ ] **禁止：** 在原生 `<button>` 已自带角色时重复添加相同角色。
- [ ] ARIA 的"第一规则"：**不要给原生 HTML 元素加 ARIA 角色或属性，除非原生元素真的做不到。**

### 4.3 不要滥用 div + onclick
- [ ] 可点击的视觉卡片/列表项，内部放真正的 `<a>` / `<button>`，而不是整个 div 挂 onclick。
- [ ] 若必须让整个区域可点，用 `<a>` 包裹或加 `role="button"` + `tabindex="0"` + `keydown` 处理（优先前者）。

## 5. 屏幕阅读器（Screen Reader）

**服务原则：可感知 + 稳健 (Perceivable + Robust)。**

### 5.1 alt 文本
- [ ] 所有 `<img>` 有描述性 `alt`（如 `alt="办公室实景照片"`）。
- [ ] 信息性图片：alt 描述图片**传达的内容**，不是"图片.png"。
- [ ] 装饰性/纯占位图片：`alt=""`（空，加在标签上）或 `role="presentation"`，让阅读器**跳过**。
- [ ] 图表/复杂图：alt 给概要，并附近提供表格或详细文本说明。
- [ ] 图标（icon font / SVG）：配文字或 `aria-label` 或 `role="img"` + 描述。

### 5.2 aria-label 使用
- [ ] 纯图标按钮（无文字）必须 `aria-label`（如 `aria-label="关闭"`）。
- [ ] `aria-label` 用于**无可见文本**但需要语义的元素，不要重复已有可见文字。

### 5.3 表单 label 关联
- [ ] **强制规则：** 每个 `input` / `select` / `textarea` 都必须有 `<label>`。
- [ ] 优先用 `<label for="id">` 与控件 `id` 关联；或用 `<label>` 包裹控件。
- [ ] 占位符（placeholder）**不能**替代 `<label>`（它随输入消失，且颜色常对比不足）。
- [ ] 关联后点击 label 自动聚焦输入框，阅读器能读出"这是干什么的"。
- [ ] 复选框/单选：用 `<fieldset>` + `<legend>` 给一组选项加标题。

## 6. 色彩之外的信息

**服务原则：可感知 (Perceivable)。** 色盲（约 8% 男性）与弱视用户无法仅靠颜色区分状态。

### 6.1 不要只用颜色传达状态
- [ ] **强制规则：** 任何状态（错误/成功/警告/禁用）**绝不能只靠颜色区分**。
- [ ] 错误：颜色（红）+ 文字提示 + 图标（如 ❗）+ 形状/边框。
- [ ] 成功：颜色（绿）+ 文字"已保存" + 图标（如 ✔）。
- [ ] 禁用：颜色变灰外，加文字标签、`disabled` 属性、或形状变化（降低不透明度 + 文字说明）。

### 6.2 图标 + 文字 + 形状补充
- [ ] 状态/重点信息：**图标 + 文字**双保险，而不是颜色 + 文字（图标对色盲友好）。
- [ ] 图表：不只靠颜色区分数据系列，叠加**形状、图案、线型、数据标签**。
- [ ] 表单校验：错误文字 + 图标 + 边框，不止红色边框。

## 7. 快速自查清单（上线前对照）

### 键盘
- [ ] 全站仅用 Tab / Enter / Space / Esc 能完成所有操作。
- [ ] 每页有 Skip link，首次 Tab 可见。
- [ ] 所有弹窗 Esc 可关、焦点陷阱、关闭后焦点返回。

### 焦点
- [ ] 所有交互元素有可见焦点圈，对比 ≥ 3:1。

### 对比度
- [ ] 正文 ≥ 4.5:1，大文本/图形 ≥ 3:1。
- [ ] 文本缩放到 200% 不破版、不裁切、不遮挡。

### 语义
- [ ] 用原生 button/a/input，无 div+onclick 反模式。
- [ ] ARIA role/label 用对，无冗余、无冲突。
- [ ] 所有 img 有 alt（装饰性为空）。
- [ ] 所有表单控件有 label 关联。

### 色彩
- [ ] 无任何状态仅靠颜色传达；图标/文字/形状兜底。

## 8. 常见踩坑速记

| 坑 | 正确做法 |
|---|---|
| `outline: none` 却无替代焦点 | 实现 `:focus-visible` 替代样式 |
| 弹窗只有关闭按钮，无 Esc | 加 Esc 监听 + 焦点陷阱 + 关闭返回 |
| div 挂 onclick 做按钮 | 改 `<button>` 或 `<a>` |
| placeholder 当 label | 用 `<label for>` 关联 |
| 图标按钮无文字 | 加 `aria-label` |
| 只靠红色表示错误 | 加错误文字 + 图标 + 边框 |
| 灰色浅底小字 | 测对比度，正文 ≥ 4.5:1 |
| 装饰图写 alt | 使用 `alt=""` / `role="presentation"` |

---

## 9. 一句话收尾

> **键盘是底线，语义是根基，对比度是门槛，颜色永远不是唯一信道。** 把无障碍当"能用的默认状态"，而不是合规补丁。
