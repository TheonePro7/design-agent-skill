# 交互与动效 · L1 学科原理

> **学科共识，非项目特定**：本文是通用交互设计 / 动效原理，不针对任何单一品牌、产品或项目。若与项目 specific design token 冲突，以项目 DESIGN.md / token 为准；本文提供的是「为什么」与「可执行阈值」。
>
> 用途：做任何界面交互与动效前的**可执行规则**速查——是规则，不是教科书抄录。每一节都给出**具体数值或判定标准**，可直接落到组件与 token 里。

---

## 〇、一句话总纲

交互的核心不是「做炫酷的动画」，而是**让每一次用户操作都有可预期的、即时的反馈，且变化不破坏布局、不打断心智**。做交互前先问三件事：**① 这个元素有几个状态没做？② 系统多久会响应、用户等多久会焦虑？③ 这个动画是在传递信息，还是纯装饰？** 三问都过关，才算合格。

---

## 一、状态转换（State Transitions）

**铁律**：每一个**可交互元素**都必须完整定义下面 8 种状态的视觉反馈，交付前逐个检查，**不许跳过任何状态**。省略状态 = 用户在某个操作下会「懵」。

### 1. 状态清单与视觉反馈

| 状态 | 触发 | 视觉反馈（必做） | 禁止 / 注意 |
|:--|:--|:--|:--|
| **Default** | 静止未交互 | 基础外观，**能看出可点击的暗示**（有主色/描边/阴影） | 别做成「看起来像纯文本」——用户会不知道怎么点 |
| **Hover** | 鼠标悬停 | 光标 `pointer` + 细微反馈（提亮背景 / 描边变色 / 轻微上浮阴影） | **只在桌面可用**；touch 上不该只靠 hover 暴露功能 |
| **Active (pressed)** | 鼠标按下 | 视觉「被压下去」：缩小到 ~0.98、背景加深、内阴影，与 hover 明显区分 | 时长要短（80–150ms）；别与 hover 混成一团 |
| **Focus** | 键盘 Tab / 聚焦 | **可见焦点环**：2–3px，与相邻背景对比 **≥3:1** | **绝不移除 focus outline**（WCAG 硬伤）；用 `:focus-visible` 让鼠标点击不出环、键盘出环 |
| **Disabled** | 不可交互 | 降对比（opacity 0.3–0.5 或去饱和）、光标 `not-allowed`、去 hover 效果、`aria-disabled` | 仍要可读；别把重要操作做成永久 disabled，要说明「为什么不能用」 |
| **Loading** | 等待中 | 骨架屏 / spinner（见第四节） | 绝不无声阻塞；等待超时要有进度（见第二节） |
| **Empty** | 无数据 | 图标/插画 + 说明 + 可选 CTA（见第四节） | **绝不白屏** |
| **Error** | 校验/请求失败 | 内联报错：红字 + 图标 + 字段下说明；字段描边变色 ≥3:1；`aria-live` | 绝不静默失败；绝不直接甩给用户裸错误码 |

### 2. 状态变更的三条硬规则

1. **禁止布局偏移（layout shift）**：状态切换**只允许**用 `opacity / transform / box-shadow / background / border-color`，**不允许**用 `width / margin / top / height` 去挤动邻居——否则整页跳动，极其廉价。
   ```css
   /* ✅ 正确：不位移 */
   .btn { transition: background .15s, transform .1s; }
   .btn:active { transform: scale(.98); }
   /* ❌ 错误：会推挤相邻元素 */
   .btn:focus { margin-left: 2px; }
   ```
2. **状态之间必须「可见的差异」**：hover / active / focus 三者**各自有别**，尤其 hover 与 active 别做成一个样（用户会分不清「我按下去没有」）。
3. **反馈时长随「动作类型」缩放**：微反馈（hover/active）80–200ms，状态切换（focus/到 loading）150–300ms——见第三节。

### 3. Focus 状态专项（键盘可达性）

- **永远保留**焦点环，仅用 `:focus-visible` 区分「鼠标 vs 键盘」：
  ```css
  .btn:focus { outline: none; }              /* 不作为默认去掉 */
  .btn:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }
  ```
- 焦点环颜色 vs 相邻背景 **≥3:1**；`outline-offset: 2px` 避免贴着边缘看不清。
- **所有交互元素**必须能用 `Tab` 到达、`Enter/Space` 触发、`Esc` 关闭（弹层/菜单）。

## 二、反馈时限（Feedback Timing）

> 分界来自人机交互响应时间研究（Nielsen 经典）：**0.1s ≈ 即时感知、1s ≈ 轻微延迟（心智仍连续）、10s ≈ 注意力极限（必须给进度 + 可取消）**。据此定出下面的硬阈值。

### 1. 响应阈值表（背下来）

| 响应时间 | 用户感知 | 你必须做什么 |
|:--|:--|:--|
| **< 100ms** | 立即 / 无等待 | 直接给结果即可——按钮按压、hover 高亮、光标闪烁 |
| **≤ 200ms** | 仍像「即时」 | **系统必须在 200ms 内给出任何形式的反馈**；做不到就立刻进「待处理态」（见下） |
| **200ms – 1s** | 可感知的轻微延迟 | 给**轻量**反馈：按钮变 disabled + spinner、或局部骨架屏 |
| **> 1s** | 流程被打断 | 给**完整**加载指示：骨架屏 / 加载器，让用户知道「在干活」 |
| **> 10s** | 注意力消散，开始焦虑 | 必须给**进度提示**（进度条 / 百分比 / 预计剩余 / 「仍在处理」消息）+ **可取消**入口。**绝不静默等待 >10s** |

### 2. 可执行规则

1. **任何点击后可能超过 200ms 的操作**，立刻把元素置入「Loading 态」并防止重复点击（`disabled` 或 `aria-busy`），而不是让用户干等。
2. **200ms 是「感知即时」的上限**——所有即时反馈（按钮、开关、hover）必须在 200ms 内完成。
3. **超过 1s 用骨架屏优于转圈**：骨架屏还原真实布局，减少「加载完成后内容跳变」的预期落差。
4. **超过 10s 给进度而非「转圈」**：转圈 10s 用户只会怀疑「卡死了」，进度条 + 文案 + 取消才能留住人。
5. **短任务直接在原位置反馈**（inline），长任务才考虑全屏遮罩；只要后台在做，就优先局部反馈，别整页卡死。

## 三、动效时长与缓动（Duration & Easing）

### 1. 时长（Duration）

**规则：动效时长 ∝ 移动距离与元素大小**——越小、越近的动作越快，越大、越远的动作越慢。一级参考基线：

| 动效场景 | 建议时长 | 默认值 |
|:--|:--|:--|
| **微交互**（hover、按钮、开关、图标、toggle、下拉、tooltip 出现） | **150–300ms** | **200ms** |
| **页面切换 / 大布局变换**（modal 浮现、drawer 滑入、页面转场、大卡片展开） | **200–400ms** | **300ms** |
| **引导/秀场动画**（intro、hero 入场） | 500ms 封顶，**< 600ms** | 克制，别拖沓 |

- **铁律**：**微交互 > 300ms 会显得「粘」「拖沓」**；**页面切换 < 200ms 会显得「生硬」**。中间值（200–300ms）最稳。
- 同组元素同时进入时**时长差 < 100ms**（Gestalt 共同命运律），否则视觉上「拆伙」。

### 2. 缓动（Easing Curve）

**缓动 = 慢起慢停或快起慢停，决定动效「质感」，比时长更重要。** 别用默认 `ease`（它偏「中速起停」，质感发闷）。**明确选曲线：**

| 曲线 | 形态 | 用在哪 | 典型实现 |
|:--|:--|:--|:--|
| **ease-out（快起慢停）** | 开头快、结尾缓 | **界面「入场/停留」元素**——元素出现、popover 展开、卡片浮现。**大多数 UI 动效的首选** | `cubic-bezier(0, 0, 0.2, 1)`（Material decelerate） |
| **ease-in-out（S 曲线）** | 两头慢、中间快 | **对称过渡**——页码切换、toggle、元素在两位置间往返、页面转场 | `cubic-bezier(0.4, 0, 0.2, 1)`（Material standard） |
| **ease-in（慢起快停）** | 开头慢、结尾快 | **只用于「离场/移除」**——元素离开屏幕、卡片删除后飞出 | `cubic-bezier(0.4, 0, 1, 1)`（Material accelerate） |
| **linear** | 匀速 | 仅限进度条 / 无限循环 spinner | `cubic-bezier(0, 0, 1, 1)` |

- **入场用 ease-out，退场用 ease-in**——这符合物理直觉：东西「进来」是从快到慢（减速进入），「离开」是加速离去。一个动效里「进」和「出」别用同一条曲线。
- **标准/稳的默认组合**（一整套直接抄）：
  ```css
  :root {
    --ease-out: cubic-bezier(0, 0, 0.2, 1);      /* 入场 */
    --ease-inout: cubic-bezier(0.4, 0, 0.2, 1);  /* 对称 */
    --ease-in: cubic-bezier(0.4, 0, 1, 1);       /* 离场 */
    --dur-micro: 200ms;
    --dur-page: 300ms;
  }
  .fade-in { animation: fade var(--dur-page) var(--ease-out); }
  ```

### 3. 减少动效（prefers-reduced-motion）—— 无障碍硬规则

- **必须响应 `prefers-reduced-motion: reduce`**。当用户开启后，**关掉所有非必要动效**：视差、滚动触发、大幅位移、无限循环动画一律去除。
- **保留**「必要的反馈」（颜色变化、状态切换、focus 环），但**把位移/缩放/循环动画降为 0 或纯淡入淡出**：
  ```css
  @media (prefers-reduced-motion: reduce) {
    *, *::before, *::after {
      animation-duration: 0.01ms !important;
      animation-iteration-count: 1 !important;
      transition-duration: 0.01ms !important;
      scroll-behavior: auto !important;
    }
  }
  ```
- **判定标准**：一个动画「去掉后用户是否仍能理解系统状态」？能 → 它在 `reduce` 下就应被移除；不能（如加载指示、状态变化）→ 保留其**非位移**的反馈形式。

### 4. 动效的意义性（非要动吗？）

- **动效必须传递信息**：入场/退场、空间关系（从哪来/到哪去）、因果关系、反馈确认。**纯装饰、无信息量的动画直接砍**。
- 一个动效若说不清「表达了什么」，它就是在给用户**添堵**，而不是增强体验。**少动比乱动好。**

## 四、三态完整设计（Loading / Empty / Error）

**铁律**：任何「结果可能为空 / 可能失败 / 需要等待」的数据区域，**都必须有完整的 loading、empty、error 三态设计**，缺一不可。这是最常见被遗漏、且最影响体验的部分。

### 1. Loading（等待态）—— 标准 pattern

- **内容区用骨架屏**：用与最终内容**同形状放置**的灰色 placeholder（`~8px 圆角`、灰底），尽量避免加载完成后的内容跳变。
- **骨架屏 shimmer**：CSS 渐变位移实现轻微流光，时长 1–1.5s 循环。
- **按钮/小操作用 spinner**：转圈时长 1s 环、转速 ~0.8s/圈。
- **规则**：
  - 骨架屏优先级 > spinner（内容类）；spinner 只用于「无明确形状」的操作。
  - **加载中禁止整页锁死**：能局部加载就局部加载，其余部分照常可交互。
  - 加载结束后**不要整块剧烈跳动**——内容渐入（`fade + 8px 上移，200ms ease-out`）。

### 2. Empty（空态）—— 标准 pattern

- **绝不白屏**。空态必须回答三问：**这是什么？为什么空？用户现在能做什么？**
- 结构：**① 图标/插画（克制，1 个主色，别用大图）② 一句说明（讲了什么/为什么空）③ 一个明确 CTA**（如「创建第一个项目」「去补全资料」）。
- **插画规则**：单色或线稿、尺寸适中（约 64–96px），不抢戏；**不要**用大面积彩色 hero 图填充空态。
- **CTA 是空态的灵魂**——没有 CTA 的空态 = 死路。永远给用户一条「下一步」。

### 3. Error（错误态）—— 标准 pattern

- **字段校验错误（inline）**：
  - 红字（色值见色彩篇：与底色 ≥4.5:1）+ 图标（⚠️）+ 该字段下方的说明文案；字段描边变红（与背景 ≥3:1）。
  - 用 `aria-live="polite"` 让读屏播报；**报错焦点要能跳到第一个错误字段**。
- **全局/服务错误**：友好文案 + **重试按钮** + 可选「联系支持」。「说明发生了什么，别怪用户、别甩代码」。
  - 4xx（用户可修复）→ 给出**指引**（「检查权限/重新登录/填完整」）。
  - 5xx（服务端问题）→ 给出**重试/稍后再试**，而非让用户「自查」。
- **关键规则**：
  - **绝不静默失败**；**绝不直接展示裸错误码/堆栈**给终端用户（内部日志可以）。
  - 错误后**必须提供恢复路径**：重试、回退、去修正、返回。

## 五、交互标准模式（Interaction Standard Patterns）

### 1. 不要发明新交互

**铁律（Nielsen 一致性启发式 #6）**：用户宝贵的时间都花在**别的产品**上——他们早已形成心智模型。**默认使用用户熟悉的模式**，只在你「有强理由且新交互明显更清晰」时才偏离。

- **标准模式清单（直接用）**：列表、单列表单、底部导航（移动）/侧边导航（桌面）、卡片栅格、**可排序分页的表格**、确认弹窗、toast 瞬时反馈、面包屑、tab、accordion、搜索框。
- **别发明**：新颖的手势、奇怪的导航隐喻、把常见控件换成自定义非标准样式。**除非你比行业标准更清楚，否则别**特立独行。

### 2. 用用户熟悉的模式（按场景）

| 场景 | 标准模式 |
|:--|:--|
| **删除/不可逆操作** | 两步确认（确认弹窗），且给「撤销 undo」的逃生通道 |
| **消消乐型重要操作**（发邮件、删除） | toast + **Undo**（如 Gmail「邮件已发送」） |
| **空数据** | 插画 + 说明 + CTA（见第四节） |
| **搜索** | 即输即搜 / **防抖 300ms** 后触发 |
| **单字段表单** | 底部提交按钮 + **Enter 提交** |
| **破坏性危险操作**（付款、批量删） | **明确警示**（红色、确认词「确认删除」而非「确定」） |

### 3. 桌面 vs 移动 hover 差异（关键）

- **桌面（有指针）**：`hover` 是**真实存在**的状态，提供 hover 反馈；但**永远不要把 hover 作为访问关键动作的唯一方式**（触摸屏、无障碍用户、键盘用户拿不到 hover）。
- **移动 / 触摸（无指针）**：**没有 hover**。**所有功能必须在「点击/触摸」下可达**。凡是「hover 才展开/才出现」的菜单、次级动作，在 touch 上等于不存在——必须改成「点击展开」。
- **触控目标尺寸**：
  - 移动端：**≥ 44×44px**（Apple HIG）或 **≥ 48×48px**（Material）。最小可接受 24×24，但必须带充足间距防误触。
  - 桌面端：可小（**≥ 28×28 / 24×24**），但 hover 已在提示。
- **hover 意图（hover-intent）**：桌面下拉/菜单在 hover 上**加 300–500ms 延迟**再展开，避免鼠标扫过误触发；触摸则靠点击，且要求能 `Esc` 关闭。
- **键盘**：一切可用 `Tab` 到达、`Enter/Space` 触发、`Esc` 关闭（与第一节 Focus 相关）。

## 六、可执行自检清单（做交互/动效时逐条过）

- [ ] 每个可交互元素都有完整 **default / hover / active / focus / disabled / loading / empty / error** 8 态？态之间可见差异？
- [ ] 状态切换**没有布局偏移**（只用 opacity/transform/box-shadow/color，没动 width/margin/top）？
- [ ] 焦点环保留、可见、对比 **≥3:1**（`:focus-visible`）？键盘可 Tab/Esc？
- [ ] **系统 ≤200ms 内给出反馈**；>1s 有骨架屏/加载器；**>10s 有进度 + 可取消**？
- [ ] 微交互时长 **150–300ms**；页面切换 **200–400ms**？
- [ ] 入场用 **ease-out**、退场用 **ease-in**、对称用 **ease-in-out**；没用默认丑 `ease`？
- [ ] 实现了 **`prefers-reduced-motion`** 降级（去位移/循环/视差，只留必要反馈）？
- [ ] 每个会为空/失败/等待的区域，**loading / empty / error 三态齐全**？空态有 CTA？错误有重试/恢复？
- [ ] 没发明新交互；用的是用户熟悉的标准模式？删除有确认 + Undo？
- [ ] **触摸场景没有依赖 hover 才能访问的功能**？触控目标 ≥44×44px？

---

> **固化记忆点**：交互 = 完整状态 × 即时反馈 × 不破坏布局。反馈时限 **200ms（即时上限）/ 1s（需加载指示）/ 10s（需进度+可取消）**。时长 **微交互 200ms / 页面 300ms**，缓动 **入场 ease-out / 退场 ease-in / 对称 ease-in-out**，忘了就补 **`prefers-reduced-motion`**。三态 **Loading（骨架屏）/ Empty（+CTA）/ Error（+重试）** 一个都别省。交互永远**用用户熟悉的模式，别发明**；移动端**别只靠 hover**。
