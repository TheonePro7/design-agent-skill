# L1 通用原理 · 排版深水区（Typography）

> 学科共识，非项目特定。这篇文章是**通用排版学科原理**，不绑定任何单一品牌、产品或项目。
> 用途：做任何界面/文档/营销页排版前的**可执行规则**速查——是规则，不是教科书抄录。
> 每一节都给出**具体数值或判定标准**，可直接落到 token 与组件里。

---

## 一、字体分类 × 适合场景

四大类，按**气质**而不是按"好不好看"选。选错类是排版翻车的首要原因。

### 1. 衬线体（Serif）
**特征**：笔画末端的衬脚（serif）+ 字怀明暗对比大。气质：**古典、可信、编辑部、人文、昂贵**。
- **适合**：长篇正文阅读（报纸/书刊）、纸质感强的品牌叙事、标题强调权威感（金融/律所/学术/媒体）、酒类/奢侈品/房产等"旧钱"类。
- **代表**（中文）：宋体、思源宋体(Noto Serif SC)、方正书宋；**英文**：Georgia、Playfair Display、Source Serif 4。
- **不要用**：数据密集型仪表盘、开发者工具、需要"数字精确感"的按钮/表格——衬线在屏幕小字号下会发糊。

### 2. 无衬线体（Sans-serif）
**特征**：无衬脚、笔画均匀、x-height 大。气质：**现代、中性、清晰、科技、信任**。**大部分界面的默认选择。**
- **适合**：数字界面、导航、按钮、正文、数据、SaaS 产品、落地页主体。屏幕阅读之王。
- **代表**：Inter、Helvetica、Roboto、SF Pro、Source Sans 3；中文：思源黑体(Noto Sans SC)、苹方、微软雅黑、HarmonyOS Sans。
- **注意**：中文网络黑体（微软雅黑/苹方）在深色背景 + 小于 13px 时容易"糊"，需配合字重或加大字号。

### 3. 等宽体（Monospace）
**特征**：每个字符占同样的宽度。气质：**技术、工程、代码、机器感**。
- **适合**：代码块、终端、日志、数据表格里的数字、参数名、API 字段、时间戳、订单号/版本号——**凡需要逐列对齐的信息**。
- **代表**：JetBrains Mono、Fira Code、Source Code Pro、IBM Plex Mono；中文等宽很少，中英混排时只对英文/数字等宽。
- **硬规则**：正文**禁止**用等宽体（长段阅读会很累）。单一行内容用等宽体时，行高要放更大（1.7–2.0）。

### 4. 展示字体（Display）
**特征**：强烈个性、极端对比、装饰性——**天生是用来当标题的**，只出现 1–2 个词。
- **适合**：Hero 标题、Logo、海报、品牌符号、大字号营销词。
- **代表**：Playfair、Space Grotesk、方正超粗黑、各种衬线 display。
- **硬规则**：展示字体**永远不能用于正文、不能用于小字号、不能用于按钮**。它只负责"大喊"一句。

### 一句话分类判定表

| 类别 | 气质 | 用在哪 | 禁用在 |
|:--|:--|:--|:--|
| 衬线 | 古典·可信·人文 | 长文阅读、权威标题、品牌叙事 | 数据面板、小字号屏显 |
| 无衬线 | 现代·中性·清新 | 界面主体、正文、按钮 | 需要历史感的品牌 |
| 等宽 | 技术·工程 | 代码、表格数字、对齐信息 | 长段正文 |
| 展示 | 个性·戏剧 | Hero、Logo、一句标语 | 正文、按钮、小字号 |

## 二、字体配对原则

配对的目标：**建立层级 + 制造对比 + 统一气质**。配对了，不用字号差异也能分出层次。

### 1. 配对的两条铁律
- **少即是多**：一个界面**最多 2 个字体家族**（通常就是"标题字体 + 正文字体"）。
- **对比要明显，气质要同频**：两类字体在气质上要么同阵营、要么刻意反差，不能"差不多又不一样"（那会像错误）。

### 2. 最稳的黄金组合：无衬线标题 + 衬线正文，或反过来
- **无衬线(标题) + 衬线(正文)** → 现代 + 人文，适合内容型/媒体型产品。`Inter 标题 + Georgia 正文`。
- **衬线(标题) + 无衬线(正文)** → 经典 + 清晰，Stripe/Claude 系走这条路：`Playfair 标题 + Inter 正文`。**这是营销页最安全的组合**。

### 3. 字重对比（weight contrast）——比用两个字体更常用
**字重组合模板（正文中，同一字体家族内造层级）：**
- body: `400`
- 标题/强调: `600` 或 `700`
- 大 display 标题: **用「轻weight 300/400」反而是高级主张（Stripe 签名款）**——要靠**字号大 + 字距紧**出气势，不是靠粗。
- 数字 / 标签: `500` 或 `600`

**硬规则**：相邻层级字重差**至少 100**（400 对 600/700）。不要 400 对 500 这种"差 100 以内"的暧昧对比——肉眼分不出，像 bug。

### 4. 避免 2 个以上展示字体
- 展示字体只留 **1 个**。
- 第二个展示字体一旦出现，版面气质立刻打架（出现"皮影戏"效果——两个都在抢戏，层次崩塌）。
- **替代方案**：想要多一层戏剧感时，不改字体，改**字号、字重、颜色、字距、大小写**来制造对比。

### 5. 配对自检清单
- [ ] 全案只有 ≤2 个字体家族？
- [ ] 展示字体 ≤1 个？
- [ ] 标题与正文气质同频（要么同阵营，要么刻意反差）？
- [ ] 相邻层级字重差 ≥100？
- [ ] 正文没用衬线/展示字体（除非刻意长文人文风）？

## 三、字号阶梯（8pt 系统）

**8pt 网格**：所有字号都是 8 的倍数，保证任意组合下间距/基线能对齐。**这是现代 UI 的基线，别用 10/15/18px 这种"半乱"的数。**（细分可用 4pt 网格，但 8pt 是主格。）

### 主阶梯（8 的整倍数）

| 字号 | 词级 | 用途 | 行高建议 |
|:--|:--|:--|:--|
| **12px** | micro | 元数据、脚注、时间戳、版权行、表单提示、按钮中极小辅助 | 1.6 |
| **14px** | caption | 次级说明、tab 标签、按钮文字、表格单元格、面包屑 | 1.5 |
| **16px** | body | **正文默认**。阅读舒适起点（低于 14 伤眼） | 1.6 |
| **20px** | body-lg | 引言、卡片正文放大、段落开头强调 | 1.5 |
| **24px** | sub-heading | 卡片标题、小节标题、表单标题 | 1.3 |
| **32px** | section | 区块/章节大标题、modal 标题 | 1.2 |
| **48px** | display | 主 Hero、page 级标题 | 1.1 |
| **64px** | display-xl | 极重大标题、品牌标语 | 1.05 |

### 8pt 网格补充规则
- **最小字号**：正文**不低于 14px**，小标签**不低于 12px**。屏幕 < 12px 直接放弃可读性。
- **阶梯之间的跳档**：相邻级别**至少差 8px**，否则层级感弱（16 与 18 看不出主次，16 与 20 能）。
- **层级 = 字号 + 字重 + 字距**三件事一起做，单靠字号爬不高级。
- **基准级**：把 `16px` 定为基准（body），往上往下全都按 8 的倍数走，间距才好算（如 `margin = 字号 × 1.5`）。

## 四、行高 / 行长 / 字距的具体数值

### 1. 行高（line-height）——单位用**倍数**，别用 px
| 场景 | 行高 | 原因 |
|:--|:--|:--|
| 长段正文（body 16–20px） | **1.5–1.7**（推荐 1.6） | 阅读最舒适，行不挤不散 |
| 标题（display） | 1.05–1.20 | 越大的字行高越要紧，才显"重" |
| 等宽体 / 代码块 | 1.7–2.0 | 等宽字形本身偏小基线，行高要更松 |
| 中文正文 | 1.6–1.8 | 中文没有小写字母 x-height 撑底，**行高要比英文再放大 0.1–0.2** |

**rule**：标题行高用小倍数（1.05–1.25），正文行高用 1.5–1.7。**别把正文行高设 1.2——那是标题的密度，正文会挤爆。** 中文正文行高取 **1.7 更安全**。

### 2. 行长（line-length / measure）——单位用**字符数**
| 场景 | 建议字符数 | 说明 |
|:--|:--|:--|
| 英文正文 | **45–75 个字符** | 理想 ≈ 60–70 |
| 中文正文 | **28–45 个汉字** | 汉字宽，45 个 ≈ 一行号了 |
| 数据表格 | 不限，但对齐即可 | 表格无视行长规则 |
| body max-width | **600–720px**（16px 基准下） | 约等于 45–75 字符的像素值 |

**rule**：一行太长（>90 字符）→ 读者扫读时眼珠会跳行 → 疲劳。一行太短（<40 字符）→ 断行过多，也累。**用 `max-width: 65ch`（或 32–34em）直接锁住最优长度**，比手算 px 稳。

### 3. 字距（letter-spacing）——多级负字距规则
**核心观念：字号越大，字距越要紧（负值）；字号越小，字距要松（正值）。** 这是现代品牌排版的签名手法（Stripe/Vercel 都走这个）。

| 字号区间 | 建议字距 | 说明 |
|:--|:--|:--|
| display > 40px | **-0.02em ～ -0.04em**（如 48px → -0.96px ～ -1.5px） | 大字要"紧凑"，越负越精神 |
| 32–40px | -0.01em ～ -0.02em | 渐进 |
| 20–32px | -0.005em ～ 0 | 中性 |
| 16–20px（body） | **0 ～ +0.01em** | 正数字距尽量 0 |
| < 14px（小标签） | **+0.01em ～ +0.08em** | **小字必加正字距**，否则糊成一片；UP/Tab 常 .06–.1em |

**硬规则（多级负字距）——一套直接抄：**
```css
h1 { font-size: 64px; letter-spacing: -0.04em; }
h2 { font-size: 48px; letter-spacing: -0.03em; }
h3 { font-size: 32px; letter-spacing: -0.02em; }
h4 { font-size: 24px; letter-spacing: -0.005em; }
body { font-size: 16px; letter-spacing: 0; }
caption { font-size: 13px; letter-spacing: +0.04em; }
```
- **别在大字号上加正字距**（会显得笨重、散）。
- **别在小字号上不加字距或加负字距**（会糊、互相粘连）。
- 大写/全大写的小字（如导航、标签）**一定**要正字距。

### 4. 行高 / 行长 / 字距速查表（可直接进 token）
| Token | 字号 | 行高 | 字距 |
|:--|:--|:--|:--|
| display-xl | 64 | 1.05 | -0.04em |
| display | 48 | 1.10 | -0.03em |
| section | 32 | 1.20 | -0.02em |
| sub-heading | 24 | 1.30 | -0.005em |
| body-lg | 20 | 1.50 | 0 |
| body | 16 | 1.60 | 0 |
| caption | 14 | 1.50 | +0.04em |
| micro | 12 | 1.60 | +0.05em |

## 五、中文字排版特有规则

**中英文排版的最大差异**：汉字是方块的，没有 x-height / 大小写之分；中西混排时存在虚空间（spacing）、标点宽度（全角 vs 半角）、断行（避头尾）三大难题。

### 1. 中英混排（CJK + Latin）
- **字号**：混排的西文（英文/数字）**字号要略小于汉字**（约汉字 0.9–0.95 倍），否则西文显得过大、透不过气。
- **基线对齐**：西文与小写/数字**基线对齐**；与汉字对齐时，让西文 `vertical-align` 保持基线，别设 middle（会飘）。
- **字间距**：中英之间**手动加一个半角空格**（或 CSS `word-spacing`），避免粘连（"AI技术" → "AI 技术"）。但中文与全角标点之间**不要**加空格。
- **字重**：混排处西文用**同一字重或略轻 100**，避免西文在中文里"跳出去"。
- **行内少量西文**（如 "CDN"、"API"）：混在中文正文里，可保留其 native「等宽/无衬线」属性，但**规模要克制**。

### 2. 两端对齐（justify）的坑
- **中文两端对齐默认是"好"的**（方块字自然撑满），**但**：
  - **英文两端对齐会产生"字距河流"**（word space 被拉伸参差）→ 长英文段落**避免 justify**，用左对齐。
  - 中英混排 justify 时，西文会被强行拉伸压缩，**造成虚空间不均** → 混排时**优先左对齐**。
- **硬规则**：中文段落主对齐用 **左对齐**。若用 justify，必须同时开**「自动撑开中文字距 + 优先末行不伸展」**（`text-align: justify; text-justify: inter-ideograph;`）+ 避免孤立的超长西文单词。
- **末尾处理**：最后一行**不要两端对齐**（避免被拉成整行宽度），保持 `text-align-last: left`。

### 3. 避头尾（kinsoku / 禁则处理）
中文断行**不允许**把某些标点放在行首或行尾。**手动排版时必须检查**：
- **禁则（不可出现在行首）**：逗号 `，`、句号 `。`、顿号 `、`、分号 `；`、冒号 `：`、问号 `？`、叹号 `！`、右引号 `”』》`、右括号 `）】`、省略号 `……`、破折号 `——` —— 这些是**行首禁则**。
- **禁则（不可出现在行尾）**：左引号 `“『《`、左括号 `（【` —— 这些是**行尾禁则**。
- **实现**：CSS 用 `line-break: strict;` + `word-break: normal;`，或在正文元素上 `hanging-punctuation` / `text-wrap: balance`（标题/正文都受益）。多数浏览器 `overflow-wrap: break-word` 可兜底长单词/网址。
- **规则**：标点不能"孤立"在首尾——要么随字（标点前空、后贴字），要么整体挤换行。

### 4. 标点悬挂（hanging punctuation）
- **原理**：让标点**挂出**文本块边线之外（或悬挂到边距），使正文左右边缘"视觉对齐"而非"被标点顶进"。中文/日文排版的关键细节。
- **哪些标点可悬挂**：行首禁则的标点（`。，、；：？！`）在行尾时**可悬挂出右边界**，避免整行被标点硬生生推出去而产生参差。
- **实现**：英文排版中 `hanging-punctuation: first allow-end`（或 `last`）。中文场景可配合 `text-align: justify` 实现标点不再被算进网格。
- **目标**：让正文块的**左右边界在视觉上是直的**，而不是被标点戳出小疙瘩。悬挂通常只对**孤立的引号/破折号**做，别全文悬挂（过度会乱）。

### 5. 中文优先级标点（优先级/排版符号层级）
指中文标点在语义和排版上的**档次和优先级**：
- **最高级**：句号 `。`、问号 `？`、叹号 `！` —— 句子终结。
- **次级**：逗号 `，`、顿号 `、`、分号 `；`、冒号 `：` —— 分句/列举。
- **引用**：引号 `“ ”`、`『 』`、`《 》`、书名号 `《》`。
- **续行**：破折号 `——`、省略号 `……`、连接号 `—`、间隔号 `·`。
- **优先级规则**：
  - **层次不可乱**：同级标点只用一种；书名号内再引用时**引号层级**要递增（`《"…"》`或`“《…》”`）。
  - **破折号/省略号占二字宽**（`——`、`……`），**不可拆行**，不可被断到两行。
  - **顿号 `、` 只用于并列**（词与词），不用在短语/句之间（那用逗号）。
  - **中文标点一律全角**（见下），英文/数字间的标点用半角。

### 6. 全角 vs 半角
| 类型 | 宽度 | 用于 |
|:--|:--|:--|
| **全角**（Full-width，`。，、；：？！“”（）《》`） | 占一个汉字宽（1em） | **中文文本的标点一律全角** |
| **半角**（Half-width，`, . ; : ? ! " ( )`） | 占半个汉字宽（0.5em） | 英文/数字、代码、URL、英文标点 |

**硬规则（全角/半角）**：
- **中文正文里的标点必须全角**（`。`，不是 `.`；`，` 不是 `,`）。这是最常见的排版 bug。
- **数字和英文用半角**（`12345`、`abc`）。中文里出现阿拉伯数字/英文时用半角，后面跟一个空格。
- **别混用**：一句话里 `你好，world.` 是错的 → 应为 `你好，world。`（中文句读用全角，英文单词内部标点半角）。
- **标点与文字间距**：全角标点前**不留空格**（自带一个字的间距感）；全角标点后**也不额外加空格**。
- **括号**：中文用全角 `（）`；括号里嵌套英文时可用半角 `()` 区分层级。

### 7. 中文排版自检清单
- [ ] 正文标点全部**全角**（。，、；：？！）
- [ ] 数字/英文用**半角**，且与中文之间**留一个空格**（"API 接口 1000 个"）
- [ ] 中英混排：西文字号略小、基线对齐、不过度加粗
- [ ] 主对齐**左对齐**；用 justify 时开了 `inter-ideograph` + `text-align-last: left`
- [ ] 行首/行尾**没有孤立的禁则标点**（。，、？" 》） | ）、（
- [ ] 引号/书名号层级正确，`——……` 没被断开
- [ ] 标题行高 1.05–1.25、正文行高 1.6–1.8（中文取 1.7）、正文字号 ≥14px

## 附：一条"判断排版好坏"的快速心法
1. 用 `browser_vision` 或截图**肉眼扫一遍**：文字有没有粘连糊、边缘有没有被标点戳出不齐、行高是不是挤。
2. 检查**层级是否一眼可读**：标题 > 副标题 > 正文 > 标签，靠「字号+字重+字距」三件套而非只靠一种。
3. 检查**行长**：正文是否落在 45–75 字符 / 600–720px。
4. 检查**空白**：这块文字周围有没有呼吸感（留白不足 → 闷；过多 → 散）。
5. 中文内容重点过一遍**第 5 节自检清单**。

> **排版不是审美，是可量化的规则。照规矩做，就不会翻车。**
